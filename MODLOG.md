# SemCraft 2 — MODLOG

Журнал работы. Всё, чего нет здесь, теряется при сжатии контекста.

## Цель
Настоящий Minecraft внутри Serious Sam Classic (TFE 1.05 / TSE 1.07). Игрок играет в Sam, камера Sam.
Скрытый MC 26.3 рендерит по камере Sam; его кадр (цвет + depth + HUD/рука) вклеивается в кадр Sam с
окклюзией. Блоки ставятся/ломаются в уровнях Sam, мобы MC ходят по полам Sam, урон в обе стороны.
Готово = работает в реальной игре + клип 20-45 с.

## Маршрут
Passthrough (как Portalcraft / MC-в-GTA V из базы знаний). Причины:
- нужен живой MC (мобы, блоки, редстоун) — порт контента не даёт;
- прошлая попытка (MC водит игрока Sam) застряла на камере/физике — здесь Sam владеет игроком и камерой,
  MC только следует (Portalcraft-схема, доказана).
Стороны:
- **Sam**: плагин Classics Patch (`SemCraft2.dll`, C++ v143, x86) — камера в `OnRenderView`, вклейка кадра
  MC сырым OpenGL (шейдер пишет `gl_FragDepth` в шкале Sam → depth-test против depth-буфера Sam),
  экспорт геометрии уровня, ввод, урон.
- **MC**: Fabric-мод `semcraft2` (Java 25, Loom) на основе MIT-примера universal-modder
  `examples/minecraft-gta5-passthrough` (FrameExporter, мискины камеры/тумана/неба).
- Связь: WebSocket 127.0.0.1 (JSON) + shared memory кадров `Local\SemCraft2Frame` + файл геометрии в %TEMP%.

## Факты движка (проверено по коду)
- `OnRenderView(wo, penViewer, apr, pdp)` вызывается сразу после `RenderView` мира (Classics Patch
  `Core/Patches/Rendering.cpp`), до оружия и HUD.
- Мир: `glFrustum(near, far)`; far<0 → 1e5. `glDepthRange(0, 0.9)` для мира, фон 0.9..1
  (`Engine/Rendering/Render.cpp:276,365`, `Graphics/DrawPort.cpp:366-380`).
- Оси Sam = оси MC (правые, y вверх, взгляд −z при heading 0). Sam forward = (−sin h, ·, −cos h).
  MC yaw = 180 − heading; MC pitch = −pitch. 1 юнит = 1 блок.
- MC 26.3 depth обратный (1 = near, 0 = пусто), линейная z = n·f/(n + d·(f−n)) (пример GTA).
- MC 26.3 баг: depth readback ставит GL_READ_BUFFER=NONE → мискин GlCommandEncoder (пример GTA).

## Грабли (gotchas)
1. `OnRenderView` получает проекцию ДО `Prepare()`: `RenderView` копирует её (`re.re_prProjection = prProjection`)
   и готовит копию. Плоскости отсечения в apr — мусор. Решение: своя копия + `DepthBufferNear/Far = 0/0.9` +
   `Prepare()` (как Render.cpp:272-278). Результат: tan L/R ±1.333, B/T ±0.75 (90° гор., 16:9).
2. Bash-инструмент агента «съедает» обратные слэши в команде (`\\n` → перевод строки) — исходники с escape
   писать только через Write/Edit.
3. Строки консоли Sam: `\` — escape. Пути в `sc_Shot` — прямыми слэшами.
4. Shell-функция с аргументами `CTString, INDEX`: второй аргумент приходит мусором (n=50 вместо 3) → один
   строковый аргумент + sscanf. Одиночный `INDEX` работает (`sc_Pillar(4)`).
5. `InflictDirectDamage` с закэшированной брашевой сущностью как инфликтором → AV в `IsOfClass+0x19`
   (проверка friendly fire в Player.es). Решение: инфликтор = сам игрок, тип `DMT_IMPACT` (самоурон
   `DMT_CLOSERANGE` Player.es игнорирует), вызов под `__try/__except`.
6. Intro.wld ~8500×8200 м, пол — гигантские треугольники: решётка по всему треугольнику не заканчивается.
   Решение: ленивая вокселизация по чанкам вокруг игрока (бины 64×64), растеризация по доминантной оси
   с обрезкой по чанку.
7. Sam объявляет уровень раньше, чем MC открыл мир → запоминать последний и строить на SERVER_STARTED.
8. Серверный игрок MC не переносится клиентскими пакетами на 32768 блоков (регион уровня) → серверный
   `teleportTo`, если расхождение > 4 блоков.
9. Лог Sam содержит цветовые коды (`^c00ff00[SemCraft2]^r`) — учитывать при grep.
10. Через `SeriousSam_Custom.exe` грузится `Entities_Custom.dll` (Classics Patch), не ванильный Entities.dll.
11. Высота мира: Hatshepsut по Y −124..1184 → overworld `min_y −1024, height 2048` (датапак в моде) +
    сдвиг oy по центру bbox, если уровень выходит за ±1000.

12. Пересылать в Sam только урон «от мира MC» (сущность, взрыв, огонь/лава). Двойник MC стоит внутри оболочки у
    стен (удушье) и пролетает пустоту при входе в мир (out of world) — это убивало Сэма даже в god mode
    (`cht_bGod` действует только при `CheatsEnabled()`).
13. Глаза двойника MC = камера Sam (ноги = камера − eyeHeight, если камера у тела), иначе прицел MC на ~0.28 м
    ниже прицела Sam (рост Стива 1.62 против глаз Сэма).
14. Блок ставится в клетку с частичной оболочкой (подъём пандуса): миксин `BlockPlaceContext.canPlace` разрешает
    замену; при сломе оболочка возвращается.
15. Extension-пакеты Classics Patch (`CExtEntityCreate`) таскают C++-объекты (`CAnyValue`) через границу DLL —
    плагин со своим CRT падает. Сущности создавать напрямую: `CWorld::CreateEntity_t` + `Initialize()`.
16. Твёрдые блоки MC в Sam = `ModelHolder2` c `Models\Editor\CollisionBox.mdl` (collision box (0,0,0)-(1,1,1)),
    `m_bActive=FALSE` (только редактор рисует), `m_bColliding=TRUE`. Модели в SE1 сталкиваются сферами (края
    скруглены). `CWorld::CastRay` пропускает editor-модели вне редактора → пули Sam проходят сквозь блоки MC,
    `sc_Probe` их не видит; оракул — физика (`tools/test_blocks.py`: свободно 10.16 м, в стенку 2.14 м).
17. Классы монстров TFE: `Boneman` (Клир), `Werebull`, `Headman`, `Eyeman`, `Walker`, `Scorpman`, `Woman`,
    `Gizmo`, `Beast`, `BigHead`, `Fish`, `Devil`, `Elemental` (`Classes\<имя>.ecl`).

18. Запись Sam: `um win record --exe SeriousSam_Custom.exe` (gfxcapture) — из Python вызывать через
    `C:\Program Files\Git\bin\bash.exe -lc` (`um` — bash-скрипт, subprocess его не находит).
19. Повороты тест-хуком накапливаются в смещении к `pa_aRotation`; прибавлять только на свежих действиях
    (`iResent < 0`), иначе повторно отправленные пакеты крутят камеру лишний раз.
20. Шрифт `um video compile` не знает «·» (квадраты) — в титрах `|`.
21. `CCastRay` берёт editor-модели только при включённых editor-моделях (WED), а `ModelHolder2` TSE сталкивается
    только при `m_bActive` (`if (m_bColliding&&m_bActive)`). Блок = активная модель (`RT_MODEL`) с
    `mo_ColorMask = 0`: поверхности не рисуются (`_ulColorMask & ms_ulOnColor` = 0), а лучи `TT_COLLISIONBOX`
    (пули, `Bullet.es`) и физика его видят.
22. Лучи `TT_COLLISIONBOX` проверяют сферы коллизии: у куба одна сфера r=0.5, на шве двух блоков и у стыка
    четырёх — щель. Пули Sam имеют радиус (`m_fBulletSize` 0.1, дробь 0.3 в одиночной игре) → утечка только у
    углов (~4% площади). `sc_Probe` (радиус 0) проходит по шву — это не значит, что пули проходят.
23. Старт Hatshepsut x = 0 — ровно шов блоков MC (x = 32768). Тесты стрельбы сдвигают прицел с шва.
24. `sc_iTestSelect=4` при томмигане переключает на миниган (та же клавиша); у минигана раскрутка → короткий
    `sc_iTestFire` не стреляет. В оракулах кольты (клавиша 2) и подсчёт `weapons: N rays` из `sc_Status`.
25. Лог MC содержит эхо команды (`command: ... say X`) → искать `[Server] X`, а не `X`.
26. Отдача взрывов MC: `ServerExplosion.getHitPlayers()` после `explode()` (миксин на RETURN) → `push` в Sam →
    `CMovableEntity::GiveImpulseTranslationAbsolute`. ×20 гасилось трением (0.94 м), ×30 даёт ~4 м.
27. Пули Sam летят от ствола (`CalcWeaponPosition`: смещение от глаз, параллельно взгляду), прицел TSE рисуется в
    точке попадания луча оружия → на 5 м он на ~1 блок ниже центра экрана. MC-луч от глаз бил выше прицела.
    `CPlayerWeapons` хранит старт последней пули: свойство 35 `m_vBulletSource` (FLOAT3D) → выстрелы в MC от него.
28. TSE `LevelsMP/1_1_Palenque`: Сэм на старте падает в озеро и плавает — вид дрейфует, прицел гуляет, оракулы
    стрельбы врут (заметил пользователь). Тесты TSE — на `LevelsMP/1_2_Palenque` (стоит на траве).
29. TSE `ModelHolder2` не сталкивался при `m_bActive=FALSE` (gotcha 21) — до этого блоки MC в TSE были не твёрдыми;
    `tools/test_blocks.py --game tse`: свободно 7.57 м, в стену 1.43 м.
30. Указатели `CEntityPointer` на сущности мира, пережившие смену мира (`StartMap` из меню-демо Intro), роняют Sam
    без диалога при загрузке. Муверы хранятся по `en_ulID` и ищутся через `wo_baBrushes` на каждом шаге.
31. `GetBoundingBox` браша — куб вокруг ограничивающей сферы (дверь 5.6×5.6×5.6). Точный бокс — по
    `bvx_vAbsolute` вершин непроходимых полигонов первого мипа.
32. `ETrigger` без линковки Entities: свой класс `CEntityEvent(7)` + `CEntityPointer penCaused` (раскладка из
    `EntitiesV/Global.h` SDK), `SendEvent` под `__try`. `MovingBrush` на `ETrigger` едет к следующему маркеру.
33. Остатки блоков от прошлых тестов твёрдые и в Sam → ходьба тест-хуком упирается в них; тесты чистят путь.
34. `tools/dev.py mc-start ... | tail` зависает: java наследует трубу stdout. Запускать без конвейера.
35. Модели SE1 сталкиваются только сферами (`CCollisionInfo::FromModel`) → на блоках-моделях «шарики», стыки —
    ямы. Плоско только у брашей. Браш на лету: `WorldBase` (класс 100, не зонирующий) + `CObject3D` с одним
    сектором, грани — `CObjectSector::CreatePolygon` (экспорт движка), затем `CBrush3D::FromObject3D_t` (FPU 53 бит),
    `CalculateBoundingBoxes`, `FindCollisionInfo`, `UpdateSpatialRange`, `FindSectorsAroundEntity`.
36. Сплошной браш (как дверь): нормали наружу (`bReverse=FALSE`) и флаг сектора `BSCF_OPENSECTOR` (+`INVISIBLE`).
    Без `OPENSECTOR` сектор — «комната» (грани внутрь): Сэм проваливается, держат только рёбра. Сверено dev-командой
    `sc_BrushInfo` с дверью уровня (нормали out 6/6, флаги сектора 0xA8).
37. Браши не удаляют на лету (комментарий в `World.cpp`) — чанк пересобирается на месте; пустой чанк получает
    проходимый куб 1 см (пустой сектор роняет игру).
38. Пересборка освобождает полигоны, а движимые сущности держат `en_pbpoStandOn` и кэш `en_apbpoNearPolygons`
    (+`en_boxNearCached`) → перед пересборкой обнулить ссылки на этот браш, иначе падение в физике тика.
39. Плагин (статический UCRT) переводит `new/delete` на `AllocMemory/FreeMemory` движка (`Alloc.cpp`): массивы
    `CObject3D` выделяем мы, оптимизирует и освобождает движок (MSVCRT.dll). ClassicsCore тоже на MSVCRT.dll.
40. `IWorld::GetLocalPlayers` при старте уровня отдаёт слот с NULL → все dev-команды через `bridge::LocalPlayer()`.
41. Hatshepsut: интро-камера (~60 с, `m_penCamera` игрока = свойство 401/40) пропускается двумя кликами огня, затем
    открывается Нетрикса — `GetGameAPI()->SetCompState(3)` (CS_TURNINGOFF). `tools/test_wall.start_level` это делает.
42. `/fill` больше 32768 блоков MC молча отклоняет — уборка тестов 33×17×49.
43. MC 26.3: кнопки мыши нумеруются с 1 (`InputConstants.MOUSE_BUTTON_LEFT = 1`, `MIDDLE = 2`, `RIGHT = 3`), не как
    в GLFW. С 0 клик по слоту игнорировался, а ПКМ (1) работал как левая — так это и нашёл пользователь.
44. MC 26.3: экран — `minecraft.gui.screen()/setScreen()`, не `minecraft.screen`; `MouseHandler.onMove` ничего не
    делает при неактивном окне (а окно MC всегда неактивно) → позиция через аксессор `xpos/ypos` + `screen.mouseMoved`,
    клики через `MouseHandler.onButton(handle, MouseButtonInfo, 1|0)` (окно не проверяет).
45. Креативный инвентарь открывается, только когда клиент уже креатив: сервер ставит CREATIVE, клиент ждёт смену
    режима и тогда открывает экран; при закрытии — снова SURVIVAL (мобы охотятся только на выживающего).
46. `pa_aRotation` в действиях игрока — накопленный угол: заморозка вида при открытом экране = вычитать из всех
    последующих действий то, что накрутила мышь (иначе после закрытия вид прыгает). Это смещение принадлежит
    сущности игрока: у новой (уровень, новая игра) `m_aLastRotation = 0`, у загруженной — своё. Хранить его в плагине
    вечно нельзя — первый же ход новой сущности поворачивает вид на всё смещение (тесты после поворотов начинали
    уровень, глядя в небо). Смещение перечитывается из сущности: `m_aLastRotation − m_aLocalRotation` (Player.es,
    свойства 401/151 и 401/154 в TFE и TSE). Править `m_aLocalRotation` напрямую нельзя: клиент уже составил
    следующее действие из старого значения, и поворот наполовину откатывается.
47. Чат Sam: `IPacketEvents::OnChatMessage` (FALSE — не показывать в чате Sam). T в Sam — «Talk»; пока открыт
    экран MC, чат Sam сбрасывается (`SetConState(0)`), чтобы буква «t» в поиске его не открывала.
48. Элитры: снятие `EPF_TRANSLATEDBYGRAVITY` гравитацию игрока Sam не выключает (каждый тик −1.5 м/с, 30 м/с²) →

    горизонталь при нулевом вводе.
49. TFE 11_AlleyOfSphinxes: `StartMap` из меню (с демо-миром Intro) вешает игру сразу после «Adding player» — даже со
    всеми подсистемами плагина выключенными (`sc_iDisable=255`); со стартом `+level Levels/11_AlleyOfSphinxes.wld`
    (`tools/dev.py sam tfe +11_AlleyOfSphinxes`) — нормально. Без плагина через `StartMap` не проверено.

    фокуса → только один удар. Миксин: в режиме стройки мышь «захвачена». И двойник летает (`flying`), а без опоры
    MC копает в 5 раз медленнее (`Player.getDestroySpeed`: `/5` если не `onGround`) → миксин ×5, пока Sam ведёт.
55. Курсор инвентаря двигался по действиям игрока (20 Гц) — выглядело как низкий FPS. Теперь каждый кадр:
    `_pInput->GetAxisValue(MOUSE_X_AXIS / MOUSE_Y_AXIS)` (пиксели × чувствительность, y вверх), колесо — ось 3.
56. Фейерверк — только из руки, как в MC (пользователь: «используются, даже когда не в руках»). `gear` шлёт `hand`
    (основная или вторая рука); ПКМ в полёте шлёт `firework`, сервер MC тратит ракету из этой руки (`consume`) и
    запускает `FireworkRocketEntity` с игроком — след и хлопок MC, разгон считает Sam. Стартовый набор кладёт 64
    ракеты во вторую руку; вторая рука не пополняется (хотбар — да).
57. Лимит кадров MC 120 → без ограничения (260): ~115-125 кадров/с до Sam (Sam ~150).
58. «Стрелы не бьют врагов»: прокси монстра — невидимый житель; ПКМ луком с прицелом на него — это разговор с
    жителем (`Mob.interact` → SUCCESS, качает головой), лук не натягивается. Миксин: прокси отвечает PASS (на обеих
    сторонах — клиент решает, использовать ли предмет). Стрелы без хозяина и из лука ранят (Клир 125 → 75).
59. MC 26.3 на SDL3: `KeyEvent(key = сканкод USB, keycode = SDL_Keycode, modifiers = SDL_Keymod)`,
    `InputConstants.KEY_RETURN = 40`, Shift = 1, Ctrl = 0x40. Коды GLFW (257 = Enter) экраны молча игнорируют —
    Enter в чате не отправлял.
60. Поршень толкает сущность через `Entity.move(PISTON)`, а у двойника (и прокси) `noPhysics = true` → `move` сразу
    делает `setPos` и не зовёт `limitPistonMovement`. Ловить надо в голове `move`, лимит 0.51 блока на ось за тик — свой.
    Сэма толкает клиентский поршень (он двигает своего игрока), монстров — серверный.
61. Сброс мира: мир void, значит всё не-оболочка — построенное. Эпоха сброса растёт; загруженные чанки чистятся
    сразу (палитра секции `maybeHas(не воздух и не оболочка)` — 1369 чанков за ~40 мс), остальные — при загрузке
    (`ServerChunkEvents.CHUNK_LOAD` → на следующем тике). Сущности несут тег `semcraft2_epoch_N`; чужая эпоха при
    загрузке — `discard`. `OnGameStart` (новая игра, `StartMap`, но не интро `sam_strIntroLevel`) → `all`;
    `OnChangeLevel`, `OnGameLoad` → `world`. Отправка — когда MC на связи.
62. Каждый старт уровня в Sam — автосейв в слоты быстрых сохранений (8 по кругу). Тестовые рестарты вытеснили
    быстрое сохранение пользователя (Великая пирамида, начало уровня). Теперь `tools/dev.py sam` копирует `SaveGame`
    в `%TEMP%\SemCraft2\savegame_backup` перед запуском.
63. Тесты в одном уровне мешают друг другу: раненый луком Клир мстит игроку (урон «от игрока») и толкает его, полёт
    уносит игрока к стене, где «блок в 3 м по прицелу» оказывается в стене (пользователь заметил лишних мобов и
    атаку Клира). `test_deeper.py`: каждая проверка на свежем уровне, после лука `cht_bKillAll`.
64. Статус MC отвечает двумя сообщениями (`status` и `client`); `request(..., "status")` оставлял `client` в очереди,
    следующий запрос `client` читал устаревший (сундук ставился по старому прицелу). `request` теперь сначала
    вычитывает очередь.
65. Имена уровней: `+level` даёт `Levels\..\Levels\X.wld`, меню — `Levels\X.wld` → разные регионы MC. Ключ региона
    теперь нормализуется (`LevelNameTest`).
66. **Краш при смене уровня** (пользователь: переход Hatshepsut → Sand Canyon, `Engine.dll` 0xC0000005 сразу после
    экспорта нового уровня). Смена уровня заменяет мир **без `OnGameStop`**; плагин держал `CEntityPointer` на браши
    блоков, монстров и снаряды старого мира и отпускал их в `OnWorldLoad` — уже на освобождённой памяти. Теперь в
    `OnWorldLoad` ссылки бросаются без отпускания (`ep_pen = NULL`, сущности старого мира остаются висеть). Оракул
    `tools/test_levelchange.py`: до правки краш, после — Hatshepsut → Sand Canyon → Tomb of Ramses, TSE Palenque 2 → 3.
67. Здоровье: `m_fMaxHealth` (401/6) — «верхнее» здоровье уровня (100; 200 на Tourist/Easy), `MaxHealth()` выше.
    Сердца MC = max(верхнее, текущее)/5 → сверх верхнего появляются новые. Сверх верхнего здоровье Сэма тает, а на
    Tourist ниже — растёт (тест с допуском).
68. Броня Сэма — только на полосе брони клиента (`LivingEntity.getArmorValue` на клиенте): атрибут брони сервера
    срезал бы урон MC, а Sam срежет его своей бронёй ещё раз.
69. Очки: событие `EReceiveScore` (Global.es, код 14: `iPoints`) — то, что шлёт умирающий монстр; своим классом, как
    `ETrigger`. `__try` в функции с объектом-деструктором нельзя (C2712) — посылка в отдельной функции.
70. Бонусы TSE: `m_tmInvisibility..m_tmSeriousSpeed` (401/160..163) — момент окончания; бомбы `m_iSeriousBombCount`
    (401/190), уменьшилось — бомба взорвана. В TFE этих свойств нет (`PropertyForId` → NULL, всё 0).
71. Третье лицо: `m_iViewState` (401/20) = `PVT_3RDPERSONVIEW` (3). Сэма прячем `en_RenderType = RT_NONE` на время
    кадра (`OnPreDraw` → `OnPostDraw`, и у предиктора). В MC камера `detached` → рисуется сам игрок; ноги шагают от
    пройденного Сэмом за тик (`calculateEntityAnimation` переопределён: двойник ставится каждый кадр, своей скорости
    нет).
72. Жемчуг: `ThrownEnderpearl.onHit` → телепорт Сэма в точку жемчуга + 25 урона (5 MC).
73. Bash-инструмент съедает `\n` в heredoc → C-строки с `\n` правятся только Edit/Write (опять).
74. Тест-хуки: `sc_iTestButtons` — кнопки действия на одно действие (128 вид от 3-го лица, 8192 бомба TSE),
    `sc_SetPlayer("hp .. armor .. bombs .. power i s")`.
